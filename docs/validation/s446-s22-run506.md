Recording is an explicitly injected library seam. Missing recorders fail before
execution. RecordResult rejects nil recorders/results, invalid run IDs, storage
errors, and missing/mismatched receipts. ExecuteTask invokes recording exactly
once, including for nonzero process exits. Recording errors preserve actual exit,
stdout, and stderr; they do not become successful delegation. A successful receipt
identifies the recorder's durable result. The recorder is responsible for committing
that result before returning its receipt. No production recorder is supplied.

Tests sync a temporary result file and read back the actual successful/failed
outcome. Those tests prove the local recording contract, not a weave lifecycle.
Workers returning no result fail closed, and unexecuted plans cannot unlock
subsequent steps or promotion. No production queue file is rewritten. No fake
weave CLI, model worker, bus mail, or relay is invoked by the new tests.

## Production route inspection and remaining gap

`pkg/weave/weave_subverbs.go` defines `start --no-spawn` as allocation only.
`runWeaveStart` in `pkg/weave/weave_impl.go` explicitly stores `allocated`, clears
the wrapper PID, and returns without running a worker on that path. Running a
separate local runner afterward does not make weave own or record its outcome.
There is no supported completion/result setter for such an allocated local seat.
The run-500 adapter's fake CLI lifecycle therefore cannot prove production
supervision, and none of those adapters or fake queue tests are brought forward.

Weave does support `start -- <tool> [args...]` and supervises that process. That
is a generic tool launch, not an API accepting the validated artifact, effect
policy, local interpreter, and recording receipt implemented here. There is no
CLI entry to this bounded local runner to connect through that route. This delivery
does not launch a model as a substitute, claim that allocation is execution, or
invent a queue mutation to mark completion. Starting without either tool argv or
`--no-spawn` currently errors; it does not itself provide a script executor.

Remaining S22 work:

1. A supported production native script seat or a guarded executable entry point
   for the bounded runner, connected to weave's real process/result lifecycle.
   It must record actual exit/output/finish state and expose that completion to
   the existing run delta provider. Add isolated end-to-end tests of that route.
2. Body-bearing sprint assignment, or an explicitly supported weave handoff route,
   with validated artifact identity and policies preserved through execution.
3. Production step-level retry/replan supervision and actual promotion integration.
   Main's promotion objects describe references; they do not publish runbooks.
4. A measured CI/CD economics comparison (success rate, tokens per success, wall
   clock). No projected model-call savings are treated as measured economics, and
   no staffing default changes are justified by these local tests.
