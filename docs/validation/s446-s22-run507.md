## Delivered

Run deltas now include `type: lifecycle` rows with persisted `state`, nullable
`exit_code`, `finished_at`, and `evidence: persisted-run`. The owning weave
resolver supplies these fields; no PID inference or queue mutation is involved.
The cursor remembers the outcome and emits changes without replay. Timestamp
comparison uses time equality rather than Go's internal timezone/monotonic
representation. Initial time filters apply to finish time. A log first appearing
after an initial cursor is accepted; replacement of an established log or a new
run start still expires the cursor. These are observed terminal snapshots, not an
append-only record of every intermediate state. Workspace/base/start evidence is
still required, including for `--since start`.

`lens.ExecuteScriptSteps` is a library orchestration entry with named sequential
steps, 0–3 retries, and an optional explicitly supplied replacement skill.
Only the failed step repeats. Retries retain its digest; replacement compilation
and policy checks produce a new content-addressed artifact before dispatch.
Failed recovery blocks dependent steps. Cancellation, policy/compile failure,
missing outcomes and non-process execution errors fail closed. Model planning
remains caller-owned and explicit; there are no implicit model calls.

`DelegationResult.PublishDAG(path, target)` publishes a standalone DAG containing
verified script bytes, digest, artifact name and pure effects. It requires a
private successful execution snapshot and matching current content identity,
revalidates the bounded script, and publishes via a no-replace link. Failed,
unexecuted, deserialized/forged or mutated results cannot publish. Existing files
are not overwritten. DAG-incompatible fence lines and invalid target names are
rejected. The runner is a trusted library boundary, not a cryptographic verifier.
The older `Promote` reference-description API remains unchanged; publishing uses
`PublishDAG` explicitly. KB publication is not added; DAG is the selected route.
