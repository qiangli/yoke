## Supported handoff

The Yoke-owned `sprint assign` command now accepts:

```sh
bashy sprint assign SPRINT STORY --repo /absolute/repo \
  --script-task /absolute/task.json --script-runner /absolute/yoke --dry-run
bashy sprint assign SPRINT STORY --repo /absolute/repo \
  --script-task /absolute/task.json --script-runner /absolute/yoke
bashy weave status RUN --json
/absolute/yoke lens --since start --cursor-out /tmp/run.cursor -t jsonl run:REPO-RUN
/absolute/yoke lens --since @/tmp/run.cursor --cursor-out /tmp/run.cursor -t jsonl run:REPO-RUN
```

Requires a Bashy build consuming this Yoke revision, and the built Yoke worker.
The installed Bashy predates these assignment flags; no global installation or
vendor configuration was changed. The integration test drives the current exported
command implementation in a separate test process and launches the actual built
Yoke worker under the current native weave process supervisor.

The task uses the run506 `lens-script-task-v1` JSON schema: embedded compiled
artifact (name, digest, base64 script), nonempty caps/effects, `help: "script"`,
`no_input: true`. The shared decoder checks the 64 KiB bound, framing, schema,
metadata, content identity, syntax and policy before allocation. Artifact paths
are informational and never read. The exact input JSON bytes become the run body;
no prose/trailers are appended and no script is recompiled at dispatch. The launch
repeats digest and policy as argv, and lens-script revalidates before execution.
The script runner is an explicitly trusted executable supplied by the caller.

Assignment uses the existing seed/link API, lease authorization and native
weave start lifecycle. It persists the body/digest/runner contract and an
`assign-script` event. Launch rechecks that contract, including argv and absence
of a model agent. PTY output is captured and the run has a one-minute wall limit.
The current story holder is retained: a script evidence run neither claims nor
auto-submits the story. Automatic or manual model takeover of these runs is
refused; explicit recovery/recompilation remains caller-owned. Existing model
assignment behavior and runtime defaults are unchanged.

No operational code or test edits a queue file directly. Supported commands and
their internal store API perform mutations; tests read durable queue outcomes.
A run's process exit is evidence, not acceptance. Allocation/link/launch failures
are not transactional; like existing assignment, a failed launch can leave a
linked run requiring explicit recovery. Already-linked stories are refused.
