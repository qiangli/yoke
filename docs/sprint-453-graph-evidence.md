## Representation and boundary

`pkg/dbgraph` implements typed node and directed edge operations on the supplemental in-memory `MemGraph` and on persistent Bonsai. Persistent typed records use only `bashy_graph_key` (indexed string) and `bashy_graph_data` (base64 of the JSON encoding of `dbstore.Node` or `dbstore.Edge`). Node and edge identities, types, direction, opaque binary properties, and revisions round trip. Isolated nodes export through `GraphTx.Nodes`; incoming and outgoing edges use the same identity. `MemGraph` has no DQL interpreter. Persistent Bonsai retains native parameterized DQL query and mutation for databases with nonportable schemas.

Logical export is a new directory with `manifest.json` and checked `records.jsonl`, format `bashy-db-export-v1` / `1.0`, graph representation `bashy-typed-graph-v1`. The manifest declares the two reserved predicates and SHA-256, byte count and record count. Memory export uses one graph snapshot transaction; persistent export uses one Bonsai query snapshot. A persistent database with another schema, an unexpected portable key, malformed record or unsupported format fails before logical mutation. Arbitrary DQL data uses native backup for fidelity; logical export makes no arbitrary DQL parity claim. Import validates the full manifest, checksum, identities, duplicate keys, revisions and edge endpoints before writing. Memory import is one atomic graph transaction. Persistent import performs one Bonsai mutation after conflict checks; it is limited to the reserved typed subset. `on_conflict=error|skip|replace` and whole-target `replace` are explicit. Typed persistent writes read/check and mutate within one category operation; raw category mutations and schema changes are refused once a typed schema exists. Non-Bashy direct native clients remain cooperative under the adapter's declared exclusion model.

**CAS admission:** `dblifecycle/owner.go` `executeReplay` enters `mutationGate` for every non-read category operation, including requests without a request ID, and holds it across the category's read-check and mutation. Bonsai's adapter holds its one-native-database-per-process slot from open through close; writable native opens hold Badger's directory lock. The `TestGraphOwnerTwoClientCAS` regression sends two separate client processes at revision 1 for each of persistent and owner-held memory mode, requires exactly one success and one conflict, and reads back revision 2. Child processes have bounded contexts. It skips short runs and awaits the manager's remote process gate. This package adds no lock registry.

Native persistent Bonsai backup is wired through `dblifecycle.Service.Backup` using `BackupTo` and an exclusive destination directory. Native restore copies the manifest and referenced backup files into a bounded private directory, rejecting escaping paths and symlinks. It replays that staged copy into a disposable Bonsai database before taking the target's exclusive claim, then calls `DropAll` and `RestoreFromManifest` on the same staged bytes. Malformed backup data therefore fails before target mutation, and caller changes after staging cannot change the restored bytes. A storage failure after target reset explicitly reports possible partial mutation and recovery from a known-good backup; this backend API does not offer an atomic restore swap. The stage is limited to 2 GiB and 1,024 manifest entries.

A portable export is bounded to 100,000 records, 64 MiB of Bonsai query JSON and 8 MiB per JSONL record. Context cancellation is checked during scans, export and import validation. Larger graphs return `limit_exceeded` instead of an incomplete interchange. This bounded representation is the package's current scale limit.

## Local gate

On the local development host with `CGO_ENABLED=0 GOMAXPROCS=4 GOFLAGS=-p=2`:

- `go test -short -count=1 ./pkg/dblifecycle ./pkg/dbgraph ./pkg/dbstore ./pkg/dbstore/bonsaidb` — PASS. Covers typed operations, revisions, process exclusion, memory→persistent→memory round trip with isolated nodes and binary properties, idempotent import, replacement, raw mutation bypass refusal, deletion cascade, external DQL schema refusal, and native Bonsai backup/restore. Restore regressions check malformed late payload leaves the target intact, staged bytes remain unchanged when the caller's source changes, and manifest traversal paths are refused.
- `CGO_ENABLED=0 GOMAXPROCS=4 GOFLAGS=-p=2 go test -short -count=1 ./cmds/db -run TestGraph` — PASS after the graph front door was mounted on the local storage batch candidate. `db graph` accepts typed JSON input or declared flags, the registered MCP command uses the same runner, and general `db export|import` routes Bonsai to graph interchange. The focused test covers a persistent typed node, isolated-node export/import, rejected foreign and duplicate flags, and MCP node retrieval.
- `CGO_ENABLED=0 GOMAXPROCS=4 GOFLAGS=-p=2 go test -short -count=1 ./pkg/dbgraph` and `CGO_ENABLED=0 GOMAXPROCS=4 GOFLAGS=-p=2 go test -short -count=1 ./pkg/dbgraph ./cmds/db -run TestGraph` — PASS after extending the independent-client regression; the non-short process test remains for the manager's remote gate.
- `CGO_ENABLED=0 GOMAXPROCS=4 GOFLAGS=-p=2 go test -short -count=1 ./pkg/dbgraph -run TestGraph` — PASS after correcting the persistent CAS child target to omit its session field. The owner call still routes by session ID. The earlier Windows process gate returned `invalid_input` because the persistent child target included a session; the manager's remote rerun is pending.

The graph package is mounted in shared CLI/MCP and atlas rows. The manager owns whole-product, independent-process and platform gates.
